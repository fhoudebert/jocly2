# Ultima - implementation status

Ultima (Baroque Chess), by Robert Abbott. Model: `src/games/chessbase/ultima-model.js`,
registered in the `chessbase` module manifest under the game name `ultima`.

## Running the tests

No build needed - the tests load the model scripts in a small sandbox
(`harness.js`) and drive `Model.Board` directly:

    node tests/ultima/rules.test.js         # 42 assertions on the rules
    node tests/ultima/consistency.test.js   # undo integrity, playouts, perft
    node tests/ultima/view.test.js          # sprite sheet / aspect mapping, rules page

## What is implemented

* All seven piece types: King, Pincer Pawn, Withdrawer, Coordinator,
  Long Leaper, Immobilizer, Chameleon.
* Multi-victim moves. The base model knows one displacement capture per move
  (`move.c`); this model adds `move.kills`, an array of piece indices, and
  hooks `ApplyMove`, `cbQuickApply` and `cbQuickUnapply` so that the Zobrist
  signature and the undo stack stay exact. `cbQuickApply`/`cbQuickUnapply`
  round-trips are asserted on every generated move of every position visited
  during the random playouts.
* Ultima-specific check detection. "Attacking a square" is unrelated to
  "being able to move there" in this game, so the graph-based
  `cbGetAttackers` of the base model is bypassed for the King: the opponent's
  replies are generated and the search stops at the first one that would
  remove the King.
* Stalemate is a win for the side that stalemates (`cbOnStaleMate = -1`).

## Known deviations from Abbott's rules

* **The Withdrawer capture is mandatory.** In the original rules, withdrawing
  from an adjacent enemy piece is optional. Making it optional means two
  distinct moves share the same from/to squares, which `Model.Move.Equals`
  (`f`, `t`, `pr`) cannot tell apart - it would need an extra field and a
  matching `Equals` override. Same remark for the Chameleon withdrawing from
  an enemy Withdrawer.
* **No suicide move.** An immobilized piece is allowed by some rule sets to
  remove itself from the board; here an immobilized piece simply cannot move.
  This changes stalemate outcomes in a few positions.
* Immobilizer versus Chameleon is implemented as mutual paralysis: the
  Chameleon adjacent to an Immobilizer is frozen by it, and freezes it back.
  Other rule sets exist.

## Not done yet

* **Piece graphics.** The view is 2D only and reads `res/ultima/ultima-picto-sprites.png`,
  a grid of 100x100 cells: one column per piece (order given by
  `SPRITE_COLUMNS` in `ultima-view.js`), row 0 for White and row 1 for Black.
  The sheet shipped today is a placeholder - a letter in a disc - meant to be
  replaced cell by cell; `view.test.js` checks that every piece still has a
  column and that the columns fit inside the PNG, so a half-finished sheet
  fails loudly instead of silently drawing the wrong piece.
* **Animation of multi-piece captures.** The base view only animates
  `move.c`; the pieces removed through `move.kills` disappear when the board
  is refreshed. A `multi-leg`-style hook is needed.
* **3D.** Not started: the game declares the `skin2d` skin only.

## Rules page

`res/rules/ultima/ultima-rules.html` is referenced by the manifest and is
generated by `tests/ultima/make-rules.py` - the page is committed, so the
generator only needs to be run when a diagram or the wording changes:

    python3 tests/ultima/make-rules.py

It ships no image of its own: the pieces in the diagrams are `<span>`s showing
one cell of the same sprite sheet as the game, positioned in percentages, so
the page follows the sheet as its cells are filled in. `view.test.js` checks
that the columns declared in the page still agree with `SPRITE_COLUMNS` in
`ultima-view.js`, which is what breaks if the sheet is ever reordered.

The page documents the two deviations listed above, so that what a player
reads matches what the model does.
* **Evaluation.** Piece values are placeholders and the positional terms come
  from the generic chess evaluation, which does not describe Ultima at all
  (mobility and immobilization dominate this game). The AI plays legally but
  weakly.
* Rules/description/credits/thumbnail resources and translations are absent
  from the manifest entry.
* The perft numbers are anchors produced by this implementation, not values
  cross-checked against another Ultima program; perft(2) = 944 is the only one
  verified by hand.
